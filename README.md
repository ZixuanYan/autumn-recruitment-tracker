# 秋招投递管理器

一个面向秋招求职者的投递管理工具，可在电脑浏览器和手机上使用。无需注册账号，投递数据默认只保存在使用者自己的浏览器中。

> 本仓库为 monorepo：根目录 = 网页版管理器（GitHub Pages 部署，实际伺服的是 `build.js` 产出的 `dist/`），`extension/` = 配套浏览器扩展「秋招求职与简历助手」源码，`services/mail-sync/` = 邮件提醒的 GitHub Action，`shared/` = 三端共用的单一事实源（阶段预设 / 企业性质 / 公司归一化 / 默认简历骨架），`test/` = 392 项测试（每次 push 由 CI 跑，不过就不部署）。

## 主要功能

- 新增、编辑、删除投递记录；阶段采用「里程碑时间线」——可自定义、可跳过笔试、支持三/四/五面等多轮，点「推进」选择下一阶段追加为里程碑
- 可选云同步：投递记录同步到自己 GitHub 账号下的私有 Gist，手机和电脑跨设备修改；不同同步口令是独立数据空间，互不覆盖可切换，支持口令加密
- 我的简历：可视化编辑个人资料与多段经历，保存后自动下发给浏览器插件供网申填表，并随云同步加密上传
- 简历 JSON 即真相：编辑器按简历 JSON 实际存在的段渲染；删除的段保存后不再出现、也不会被写回
- 记录公司、岗位、城市、投递日期、当前阶段、最近安排和下一步行动
- **关键时间**（v4.19.0，v4.24.0 起两类分组）：一条记录可填多个时间，按**截止时间**（要赶的硬期限，参与倒计时与日历导出）与**开始时间**（面试 / 笔试测评 / 其他）分组；**是否全天由「有没有填时刻」决定**，所以截止也能精确到分钟，最后 24 小时按小时倒计时。邮件里「3 日内」这类相对期限由 AI 按收信时刻换算（标「按邮件推算」并保留原文），时区走 `MAIL_TZ_OFFSET` 变量（默认 `+08:00`）
- 左侧独立入口：总览（统计 + 洞察）/ **日历**（v4.27.0，月历看每天的开始时间与截止时间；v4.28.0 起已完成聚合为浅绿「N 条已完成」；v4.30.0 起月历瘦身成**定位器**——窄屏只排事件圆点，阅读交给按日分组的**日程流**：未来 7 天 + 逾期置顶 + 点选日期全量明细插队；v4.31.0 起同一封邮件牵动的多个岗位**合成一行**并可批量标记完成 / 批量推进）/ 投递记录（表格 / 看板双视图台账，v4.8.0 从总览独立成页）/ 我的简历 / 工具 / 邮件提醒（可选）
- 工具视图集中管理数据安全与云同步，卡片实时显示快照数量与同步连接状态
- 今日投递统计与洞察（阶段分布 / 转化漏斗 / 需要关注 / 城市分布 / 企业性质 / 投递节奏 / 各阶段停留）在总览；**日程与月历在日历页**（v4.30.0 起合并为按日分组的日程流，v4.31.0 起同邮件同事项的多个岗位合并展示、可批量操作，对应的截止 / 逾期提醒也合并成一条）；搜索、阶段筛选、排序、**同企业收纳**（v4.25.0 起组头是公司卡片：公司名 + 岗位数 + 一排岗位胶囊，折叠时就是多岗位扫描视图；v4.26.0 起可一键全部折叠 / 展开）与表格 / 看板切换在投递记录页
- **已完成的时间一眼可辨**（v4.27.0）：当前阶段标记完成后，该记录名下的截止时间不再倒计时——「最近时间」列给灰显日期加绿色「已完成」徽章，倒计时从表格、看板与「需要关注 / 未来安排」里同时退场；推进到下一阶段后自动恢复。详情抽屉的关键时间逐条补「（已完成）」标注。「已完成 N 天，考虑推进」提醒按用户反馈整体移除
- **邮件里的测评链接可直接点**（v4.26.0）：Action 从邮件 HTML 的 `<a href>` 里抽出链接（只认 http/https，退订类模板链接丢掉，一封最多 8 条）随归档带回，记录详情的「相关邮件」给成一排可点胶囊，不必回邮箱翻；邮件原文里的地址也会自动变成可点链接。链接由代码抽取而非 AI 生成。台账「最近时间」列里，**已推进过去**的安排不再标「已过期」，只转灰保留历史
- Apple 风格设计系统（v4.10.0 起）：SF 排版、Apple 蓝强调、发丝线卡片、胶囊按钮与输入框、磨砂玻璃侧栏、细线 SVG 图标
- 配套“秋招求职与简历助手”插件：网申页简历字段点击速填（左键填入聚焦框、右键复制、可搜索）、一键收录岗位，未打开本页时进暂存箱
- 插件纯离线运行、不发起任何网络请求（v4.0.0 起已移除整页自动填充与 AI 辅助填写，改为用户主导的逐字段速填，跨站通用、零误填风险）
- 浏览器本地自动保存、历史快照、JSON 导入与导出备份
- 支持安装到 iPhone、Android 手机桌面，像普通 App 一样打开

## 数据与隐私

- 每位使用者的数据独立保存在自己的浏览器中，其他人无法看到或修改。
- 云同步是可选功能：开启后数据只同步到你自己的 GitHub 私有 Gist；设置口令后上传前先加密，GitHub 只保存密文。
- **未设口令时上传的是明文**，其中包含「相关邮件」的**原文快照**（v4.23.0 起正文无条件归档，为了让"点开记录就能看原文"不需要先配密钥）。secret gist 凭 URL 即可被读取，不放心就设一个同步口令——云同步弹窗里的「云端存储」会实时标注当前是密文还是明文。
- 网页更新不会主动覆盖已有投递记录。
- 未开启云同步时，电脑与手机、不同浏览器之间**不会自动同步数据**。
- 换设备时可开启云同步互通，或先“导出投递记录”，再在新设备的“数据安全”中导入 JSON（备份中含投递记录与简历）。
- 清理浏览器网站数据、使用无痕模式或卸载浏览器可能造成记录丢失，请定期导出备份。
- 顶栏“分享报告”可导出单文件 HTML 招聘进展快照，适合发给老师或朋友只读查看；它只含总览、阶段进度和投递记录，不含简历、邮件、行动、日程或敏感字段，也不会随台账自动更新。需要恢复数据时仍请使用“导出投递记录”JSON。

## 改网页版代码的正确姿势

`index.html` 是**构建产物**。直接改它，下次构建就被覆盖；只改 `src/` 而忘记构建，CI 会红
（`npm test` 的前两步是 `node build.js && diff -q dist/index.html index.html`）。

```bash
# 改完 src/ 下的任何文件之后
npm run build:write     # 生成 dist/，并把 index.html 写回仓库根
npm test                # 会再构建一次并断言产物与入库的那份一致
git add src index.html  # 两者必须在同一次提交里，否则 CI 判定为漂移
```

各部分在哪：

| 要改什么 | 去哪 |
| --- | --- |
| 配色 / 圆角 / 阴影 / 排版 | `src/styles/apple.css`（Apple 覆盖层，级联在后，改这里就够） |
| 重置样式、表格骨架、响应式断点 | `src/styles/base.css`（基础层） |
| 截止日 / ICS 导出 / 公司分组 / 洞察统计 / 查重 / 城市统计 | `src/core/` 六个文件（纯函数，零 DOM 依赖，可单测） |
| 邮件匹配的纯逻辑（模糊匹配 / 过滤 / 状态合并） | `src/mail/pure.js`（完全自洽） |
| 其余（存储、云同步、渲染、事件绑定、启动） | `src/app/` 三段，数字前缀即拼接顺序 |
| HTML 骨架 / head / meta | `src/template.html`（两个顶格标记是 CSS 与 JS 的插入点） |

新增文件必须登记进 `src/bundle.js` 的清单，否则它永远不会进产物——`web-check.js` 的
孤儿守卫会红并点名是哪个文件。模块插入标记（形如 `__MODULE:xxx__`，外面包一对块注释符）
必须**顶格**：带缩进的话那几个空格会残留进产物。
