# 秋招投递管理器｜安装与使用教程

在线地址：<https://zixuanyan.github.io/autumn-recruitment-tracker/>

## 一、电脑网页版

1. 使用 Chrome、Edge 或 Safari 打开在线地址。
2. 无需注册，进入后即可新增投递记录。
3. 建议收藏网页，后续固定使用同一个浏览器打开。

网页会自动保存新增、编辑、删除和推进阶段后的数据。刷新网页通常不会丢失记录。

## 二、iPhone 安装

1. 使用 Safari 打开在线地址。
2. 点击 Safari 的“分享”按钮。
3. 选择“添加到主屏幕”。
4. 点击右上角“添加”。
5. 返回桌面，点击“秋招管理”图标。

如果链接在微信中打开，请先通过右上角菜单选择“在 Safari 中打开”。

## 三、Android 安装

1. 使用 Chrome 打开在线地址。
2. 点击网页中的“安装到手机”；如果没有显示，打开 Chrome 菜单。
3. 选择“安装应用”或“添加到主屏幕”。
4. 确认后从手机桌面打开。

## 四、浏览器插件安装（仅电脑）

1. 获取插件「秋招求职与简历助手」（v5.5.0）：克隆或下载本仓库后，插件源码位于 `extension/` 目录；也可在线查看 <https://github.com/ZixuanYan/autumn-recruitment-tracker/tree/main/extension>。
2. Chrome 地址栏输入 `chrome://extensions/`；Edge 输入 `edge://extensions/`。
3. 开启右上角“开发者模式”。
4. 点击“加载已解压的扩展程序”。
5. 选择仓库里的 `extension/` 文件夹（其中含 `manifest.json`），不要选择 ZIP 文件。
6. 安装后建议通过浏览器右上角的拼图图标固定插件——**固定后点它就能打开侧边面板**，这是插件的主入口。

在线网页版一般不需要开启插件的“允许访问文件网址”权限。

**浏览器版本**：侧边面板需要 Chrome / Edge **114 或更新**。更低版本上点图标不会打开面板，但页面上的收录胶囊仍然可用（收录功能不受影响）。

### 插件使用

插件有两个入口，分工不同：

- **侧边面板**（主入口，完整功能）：点浏览器工具栏的插件图标，或按 Ctrl/⌘+Shift+F。面板由浏览器管理、**不遮挡网页**（页面会变窄而不是被盖住），所以可以一边看网申表单一边点字段填入。里面有：一键收录、暂存箱、简历字段库、打开网页版。
- **页面上的收录胶囊**（快捷入口，只做收录）：点它弹出一张紧凑表单。**胶囊可以拖着走**——按住拖到页面空白处松手，它会自动吸附到最近的左/右边缘，位置会记住（刷新页面、换个网站都保持）；表单跟着胶囊出现在空白处，不挡住你正在看的内容。

常用流程：

1. 打开招聘网站的岗位详情页或投递记录页。
2. **填表**：先点网页里的输入框，再点侧边面板「简历字段」里对应的字段即可填入（**右键**字段可复制内容，顶部搜索框可按字段名/内容过滤，命中的分组会自动展开）。
3. **收录岗位**：点页面上的胶囊（或侧边面板里的「识别当前页面」），核对识别出的公司、岗位、城市、日期、阶段，企业性质手动选一次，然后保存。
4. 管理器已打开时会实时推送并弹窗确认；没打开时先进暂存箱，之后打开网页版逐条确认入库。

面板顶部有**当前页状态条**，会告诉你现在这个页面能不能收录 / 速填（浏览器内部页、扩展商店页、网页版管理器页都会明确说明并禁用相应按钮）。切换标签页后状态自动更新，并会收起上一次的识别结果，避免把 A 公司的岗位存成 B 公司的链接。

招聘网站结构可能改变，插件识别结果必须在保存前人工核对。手机浏览器不能安装此插件。

### 插件更新

1. 下载并解压新版插件。
2. 使用新版文件替换旧插件文件夹。
3. 回到扩展程序管理页面。
4. 点击插件卡片上的“重新加载”。
5. 刷新招聘网页和投递管理器。

## 五、基本使用

- “新增记录”：填写公司、**机构 / 子公司 / BU（v4.11.0，选填）**、岗位、城市、**企业性质**、投递日期、**关键时间（v4.19.0）**、**意向度**、当前阶段和下一步行动；展开“更多字段”可再填**内推人 / 薪资**（批次与渠道两个字段已在 v4.11.0 删除，区分职责由“机构”接替）。
- “关键时间（v4.19.0，v4.24.0 起两类分组）”：一条记录可以填**多个**时间。下拉按**两类**分组显示——**截止时间**（必须赶的硬期限：网申 / 测评 / 笔试 / 签约截止，参与倒计时与排序）与**开始时间**（到点要参加的事：**面试**、**笔试测评**、**其他**如宣讲会）。**类型只是标签**：一条时间是"全天（只有日期）"还是"定时（精确到分）"，由**你填不填时刻**决定——所以**截止也能精确到分钟**（v4.24.0）。这修的是一个很实际的损失：邮件里那句最有用的话「请在 9 月 17 日 18:00 前完成」，此前因为"截止被写死成全天"而被削成 `9/17`，倒计时在 17:00 时还显示「截止 · 今天」，看不出只剩一小时。点「＋ 添加时间」加一条，行内可改类型 / 日期 / 时刻 / 删除（可以一条都不填，时刻留空即只有日期）。此前只有「安排时间」和「截止日期」两个固定字段——笔试与面试挤在同一个字段里，看板、台账与日历上都写着「最近安排」，分不清是哪种；一次笔试既有开始时间又有链接失效时间时也只能记一个。**旧的 scheduleAt / deadline 会在读取时自动迁成带类型的事件，老记录不用改**，也不会留下两份时间。
- “企业性质（v4.6.0）”：央国企 / 私企 / 外企三档，也可留“未设置”。第二档 v4.11.0 起叫**“私企”**（原“民企”），老记录会在读取时自动归一，不需要你改任何数据。插件一键收录时同样能直接选（收录表单里与“投递日期”并排）。选好后台账公司名旁、看板卡片、详情抽屉与 Offer 对比矩阵都会显示带色徽章，洞察里会按这三档统计投递数与 Offer 数。**不会自动猜测**——页面上没有可靠依据判断企业性质，猜错比留空更糟；没选的会归到“未设置”，洞察里会写明还有几条待补填。
- “推进”：弹出选择要推进到的阶段（可跳过笔试、可三/四/五面、可自定义），追加为该投递的时间线里程碑；当前阶段 = 最新里程碑。弹窗里可填**里程碑备注**（v4.8.0，上限 60 字，如“HR 电话通知、腾讯会议二面”），留空也可以——填了三个月后回看时间线才有上下文。
- “标记完成（v4.18.0，v4.27.0 扩展）”：有些阶段是**任务**（典型是测评 / 笔试 / 机试）——做完了不等于流程进入下一步，结果可能还没出。点台账行里的「标记完成」（或详情抽屉里的「标记本阶段完成」），只把**当前这条里程碑打勾**（当前阶段旁显示「已完成」，看板卡片标「已完成 · 待推进」），**不会**推进、也不换列；再点一次「取消完成」即可撤销，误点后 6 秒内提示条上还能点「撤销」。完成后该记录不再计入「停滞」，也不再出现在「需要关注」里（v4.27.0 起连「已完成 N 天，考虑推进」的提醒也一并移除——已完成的事不再催你）。**当前阶段标记完成时，该记录名下的截止时间也一并了结**：表格「最近时间」列给灰显日期加绿色「已完成」徽章、倒计时撤下，「未来安排」与「需要关注」同步退出；推进到下一阶段后截止自动恢复。编辑记录时也能在**时间线每一行**上直接勾「完成」。这与「推进」是两个独立动作：做完一步、稍后再决定推到哪一步。
- “投递记录视图（v4.8.0）”：台账从总览独立成「投递记录」页（左侧导航第 3 项——v4.27.0 起第 2 项是「日历」，`#/records`），独占整屏；表格 / 看板切换、搜索、阶段筛选、排序都在这一页。总览则专注统计与洞察（v4.29.0 起未来安排迁到了日历页）。（旧书签 `#/records` 依旧直达本页。）
- “日历视图（v4.27.0，v4.28.0 / v4.29.0 扩展）”：左侧导航第 2 项（`#/calendar`），所有安排集中在这一页。**顶部是「未来安排」**（v4.29.0 从总览迁来，最多 6 项、逾期置顶，宽屏自动多列卡片；旧书签 `#/upcoming` 也重定向到本页）。下方宽屏为**左月历、右当日明细**两栏（≤1100px 回落为上下堆叠）：月历 6 行 × 7 列（周一起始），关键时间按日落格——截止（红）、面试 / 笔试测评 / 其他（蓝）、已完成聚合为浅绿「N 条已完成」、逾期未处理（红点标记在日期旁 + 条目红边）；每格最多 3 条，超出收进「+N」（悬浮看明细）。**点任意日期**，右侧面板列出当天全部条目（时刻 / 类型 / 公司岗位 / 状态，含已完成），点行直达详情抽屉；再点同一天收起。点格内条目会同时选中该日并打开抽屉。标题行显示「本月 N 项（截止 X · 已完成 Y）」；周末两列浅底便于按周扫读。与「未来安排」的分工：那份是**前瞻清单**（只看接下来要做什么），月历是**事实视图**——已完成的聚合成绿行、点开仍能看到明细。标题行还有「‹ ›」翻月、「今天」回当月、「导出 .ics」把安排写进系统日历。
- “看板视图”：在「投递记录」页右上角“表格 | 看板”切换；**把卡片拖到目标列即等于推进阶段**（同样追加里程碑），往更早的阶段拖会二次确认。偏好记在本机。
- “看板布局（v4.17.0）”：从上到下是 **Offer 横带 → 推进投放区 → 进行中阶段列 → 已结束横带**。Offer 与已结束此前是**常驻列**，即使 0 条也各占一列（实测 5 列里 2 列常年是空的，白占约 40% 横向宽度，而阶段列是横向滚动的，推进到一面 / 二面变 7 列时必然要左右拖）；它们是**终态**而不是流水线环节，所以改成上下两条整宽横带，中间的列只保留真正有记录的阶段。两条横带**同样是拖放目标**，拖进去与拖到列里效果一致；空的时候整条收成一根细条（提示写在头部），不留空白区。Offer 横带左侧有一道绿色标记，与台账表格里 Offer 行的语义色一致。
- “看板推进投放区（v4.8.0）”：Offer 横带下方有一条整宽虚线区（不随阶段列横向滚动）。因为看板列只生成“当前有记录的阶段”（v4.17.0 起 Offer / 已结束 已移出列、改由横带承载），想推进到三面 / 交叉面这类**当前没有列**的阶段时无列可拖——把卡片拖进投放区即可**复用推进弹窗自由选阶段**（含自定义阶段、改日期、填备注）。“直接拖到阶段列”的一次拖拽快捷路径仍保留。拖到“已结束”横带会改为打开弹窗并预填结束原因引导（拒信 / 主动放弃 / 超期未响应），而不是直接推进。
- “看板增强（v4.8.0）”：停滞超 14 天的卡片标红并显示“停滞 N 天”（口径与洞察一致；**终态除外**——v4.17.0 起 Offer 与已结束的卡片不再显示截止 / 最近安排 / 停滞，事情已经结束了还催你跟进只是噪声。意向度星标也只在 Offer 横带的卡片上显示，那是比较 Offer 时才用得上的排序信号）；点**列头或横带头**把阶段筛选设为该阶段并切到表格视图看全部明细（键盘 Enter / Space 同样可用）；卡片聚焦时按 `A` 直接打开推进弹窗（HTML5 拖拽对键盘不可用，这是键盘可达的推进路径）。
- “详情抽屉”：点台账里的**公司名**、看板卡片、未来安排卡片或洞察里的卡点条目，右侧滑出详情——完整里程碑步骤条（含每步间隔天数）、关键信息、**笔记 / 面经**（可增删）、同公司其它投递，底部可直接推进 / 编辑 / 导出该记录到日历 / 删除。
- “编辑/删除”：修改或移除记录（删除可在提示条里撤销）。
- “搜索与筛选”：在「投递记录」页按公司、**机构**、岗位和阶段查找记录；排序支持“最近时间优先 / 投递日期 / 最近更新 / 公司名称”（v4.19.0 起叫“最近时间”——排序看的可能是一条截止，不再只有安排）。
- “同企业收纳（v4.11.0，v4.25.0 起组头是卡片）”：表格上方的独立开关（**不再是排序选项**——原先两者互斥，想收纳就用不了“最近时间优先”）。打开后同一家企业的投递收进一个组，组头是一张**公司卡片**：左侧公司色条 + 公司名 + 岗位数，下面一排**岗位胶囊**（岗位（机构）+ 阶段徽章）——折叠时它就是扫描视图，不用展开也能看清这家每个岗走到了哪一步；胶囊可**悬浮看明细、点击直达详情抽屉**。展开后胶囊下方是完整明细行，与胶囊一一对应（筛选时同源，不会对不上）。组间与组内顺序都跟着你选的排序走，折叠状态记在本机（不上传）。机构**不单独成层**——它就标在每一行的公司名后面（`招商银行 · 杭州分行`），再套一层折叠组头只是把明细往右推、多一次点击。组一多，逐个点组头太麻烦：开关旁边有一个**一键折叠按钮**（v4.26.0，只在收纳打开、且是表格视图时出现），还有展开的组时它写着「全部折叠」，全折叠好了就翻成「全部展开」。它只作用于**当前筛选出来的**那些组——先筛再折叠不会顺手改动被筛掉的公司的折叠状态。
- “最近时间”列的逾期红字（v4.26.0）：这一列显示最近的一条关键时间。**已经推进过去**的安排（流程已走过它，或那一步已标记完成）照常显示日期，但转成灰色、不再标「已过期」——事情做完了，剩下的只是历史，天天亮红灯会让真正的逾期淹没在噪声里。**没人处理**的逾期仍然是红字 +「已过期」。注意一个边界：同一天推进（一面 9/12、二面的里程碑也填 9/12）不算“走过它”，那天仍会显示逾期——用「标记完成」即可消除。v4.27.0 起：已了结的时间在灰显之外还有一枚绿色**「已完成」徽章**，当前阶段标记完成时名下的截止（哪怕还没到）也按已了结处理、不再挂倒计时。
- “同公司多岗位”：一家公司投多个岗位可以分别记录，**区分信息写进岗位名的括号里即可**——`后端开发工程师（深圳）` 与 `后端开发工程师（北京）`、`客户端开发（iOS）` 与 `客户端开发（Android）`、`产品经理（提前批）` 与 `产品经理（社招）` 都会被视为不同岗位；同一家企业的不同分行 / 子公司 / 事业部则用**“机构”字段**区分（v4.11.0 起接替已删除的“批次”）。填写公司名时，输入框下方会实时显示“该公司已有 N 个岗位：…”（与当前所填岗位相近的那项标黄），录入时就知道自己是在加第二个。公司名旁出现 `+N 岗位` 标记（悬停看各岗位与阶段）；打开“同企业收纳”开关后同公司相邻、组头即那张公司卡片（岗位胶囊一排看完，可折叠）。公司名填成“XX分行 / XX支行 / XX分公司”这类形态时，输入框下方会出现一条**“拆成企业 + 机构”建议**，点了才拆、拆完两个框都还能改。含“有限公司 / 股份 / 集团”的完整法人名**不会**给建议（那种情况企业名的结尾没法可靠定位，宁可让你自己填）；“事业部 / 研究院 / 子公司”同样不给建议，但字段本身照样能手填这些值。
- “查重规则（v4.5.0）”：判定分四档，**任何一档都不会静默拦截或静默改写你的记录**——
  ① 同投递网址，或“同公司 + **同机构** + 岗位名完全相同（忽略空格/大小写/全半角）” → 弹「疑似重复投递」，可选“编辑已有记录”或“仍然新增”；
  ② 同公司 + 岗位名相近（括号里是不同城市/方向，或**机构不同**） → 弹「疑似同岗位不同方向」，主按钮是“是独立投递，新增”；
  ③ 同公司但岗位无关 → 不打断，只在保存提示里附一句“该公司名下现在共 N 个岗位”；
  ④ 按 Esc 或点遮罩关掉确认框 → 中止本次入库，什么都不写。
  公司名判定与页面上的分组、配色、聚合排序**用的是同一套规则**（“腾讯”与“腾讯科技（深圳）有限公司”算同一家，“星海科技”与“星海互娱”算两家）。
- “洞察”：面板按**概览 → 行动 → 转化 → 明细**排列——① 6 项指标（覆盖公司 / 覆盖城市 / 在流程中 / 停滞 >14 天 / 已拿 Offer / 需要关注）② **阶段分布**（当前存量按阶段计数；v4.11.0 提到整宽第 2 位——原先挤在两列 grid 的右列，14 个色阶块每块只有约 44px，灰→蓝→绿的递进看不清）③ 转化漏斗（投递 → 笔试/测评 → 面试 → Offer，可切换记录口径 / 公司去重口径）与“需要关注”清单（截止临期或逾期、安排已过但阶段未推进、停滞超 14 天、同公司多岗位在流程中，点击直达该记录）并排④ **城市分布**与**企业性质** ⑤ 近 14 天投递节奏与各阶段平均停留 ⑥ Offer 对比。面板右上角可切“精简”，只留 ①②③（含阶段分布；偏好记在本机，不上传）。全部在浏览器本机计算，不联网。
- “城市分布（v4.6.0）”：每座城市一行，显示投递数与其中拿到 Offer 的数量，条形底色表示投递量占最多城市的比例、实色部分表示其中的 Offer。城市名会先归一化（`深圳市` = `深圳`、全角字母 = 半角），`待确认 / 待定 / 不限` 这类占位值算“没填城市”，灰显排在最后且不计入“覆盖 N 个城市”。**一条记录写了多个城市（`深圳/广州`、`北京、上海`）会在每个城市各计一次**，所以各城市投递数之和可能大于台账条数，面板说明里写明了这条口径。
- “企业性质统计（v4.6.0）”：一条 100% 堆叠比例条 + 固定 4 行图例（央国企 / 私企 / 外企 / 未设置，各档投递数与 Offer 数）。图例为 0 也会出现，便于分辨“这一档一条都没有”和“没渲染出来”；未设置占比会写进说明提醒补填。
- “悬浮看明细（v4.6.0）”：停在指标卡上看**口径说明**（例如“停滞 = 仍在流程中，且最新一条里程碑距今 ≥14 天”），停在城市行上看**该城市每条投递**（公司 · 岗位（机构）+ 阶段），停在企业性质色段上看**该档公司清单**（每家几个岗位、最好走到哪一步），停在台账收纳组头的**岗位胶囊**上看完整信息（岗位名过长时会被省略号截断）。键盘 `Tab` 聚焦即弹出、`Esc` 关闭；手机等无 hover 设备点一下切换。浮层靠边时会自动翻转，不会溢出屏幕。
- “Offer 对比”：手里有 2 个及以上 Offer 时，洞察面板自动出现对比矩阵（公司 / 岗位 / 城市 / 薪资 / 意向度 / 签约截止 / 最新备注），按意向度排序。
- “关键时间与日历”：填了**截止**的记录会在台账显示倒计时（3 天内黄、逾期红）。**只填日期的截止按日历日判定**——当天到期显示「今天」而不是已过期（v4.21.0 修掉的正是这一处），这天一整天都不算逾期；**填了具体时刻的截止按时刻判定**（v4.24.0）——「今天 18:00 截止」会显示「截止 · 今天 18:00」，最后 24 小时内改成**按小时播报**（「还剩 3 小时」），过了点则显示「已过期 2 小时」。截止与**面试 / 笔试测评 / 其他**一起进入“未来安排”（逾期置顶）。**已被了结的时间会退出这两个前瞻清单**（v4.23.0）：标记完成之后（完成日不早于事件日），或流程已经推进到更晚的里程碑之后，那条安排不再出现在「未来安排」与「需要关注」里——做完的事不该继续以“逾期”的姿态催办。两处刻意的例外：**截止不适用后半条**（硬期限的逾期不因后来推进了阶段就消失），**当天到期且尚未标记完成**的安排照旧提醒。表格的「最近时间」列与看板卡片不过滤，那里保留历史事实。表格的「最近时间」列会带上类型（如「面试 · 9月20日 14:00」「截止 · 9月25日」），看板卡片同理。点日历页头部的“导出 .ics”或工具页“导出 .ics 日程”，生成的 `.ics` 文件双击即可加入系统日历（本机生成，不联网；只有日期的按全天日期导入，带时刻的按具体时刻导入——截止的时刻同样不会被丢掉）。
- “快捷键”：`⌘K` / `Ctrl+K` 打开命令面板（搜记录、跳页面、执行动作）、`N` 新增投递、`A` 看板卡片聚焦时打开推进弹窗、`/` 跳到「投递记录」并聚焦台账搜索、`?` 打开面板看提示、`Esc` 关闭抽屉或弹窗、抽屉笔记框里 `⌘` / `Ctrl` + `Enter` 快速提交。
- “导出投递记录”：下载带日期的 JSON 备份（含投递记录与简历），不会修改现有记录。
- “数据安全”：导入备份、恢复数据或查看本地快照。

> 首次打开时台账里会有 5 条示例数据（星海科技、山岚智能、青禾互娱、远帆咨询、拾光设计），只用于认识界面。洞察位置的引导卡提供“清空示例并开始记录”（清空会写删除标记，即使已开云同步也不会被合并回来）；示例数据也绝不会参与云同步合并，不会被推到你的 Gist 里。

## 六、邮件提醒（可选，自动解析招聘邮件）

「邮件提醒」视图（左侧导航第 3 项，`#/mail`）把你 QQ 邮箱里的招聘邮件（面试 / 笔试 / 测评 / Offer / 拒信）解析成结构化建议，逐项人工复核后并入台账。它依赖一个你自己部署的定时任务，默认不开启。

启用步骤（进阶，需要一个 GitHub 账号）：

1. 先在「工具 → 云同步」开启云同步——邮件建议随云同步从你自己的私有 Gist 读取。
2. 打开模板仓库 <https://github.com/ZixuanYan/autumn-mail-sync-template>，点绿色的「Use this template」→「Create a new repository」，在**你自己账号下**创建一个**私有**仓库（务必选 Private；名字随意，本文后面用 `autumn-mail-sync` 指代它）。模板里就是全部配套脚本（IMAP 拉取 + AI 解析 + 只写 Gist 的 `mail-suggestions.json`），**你不需要写任何代码**。
3. 在你的邮箱开启 IMAP 并生成**客户端授权码**（QQ / foxmail：16 位授权码；163 / 126：客户端授权密码——都不是登录密码）；准备一个 DeepSeek / 阿里百炼 API Key；拿到云同步用的 Gist ID 与一个 `gist` 权限的访问令牌。用 163 / 126 的话另需一个 IMAP 主机变量，见下面第 5 步（QQ 不用设）。
4. 在该私有仓库的 Secrets 配置 `MAIL_USER`/`MAIL_PASS`（邮箱地址与**客户端授权码**，不是登录密码）/`AI_BASE_URL`/`AI_API_KEY`/`AI_MODEL`/`GIST_ID`/`GIST_PAT`；旧名字 `QQ_EMAIL`/`QQ_AUTHCODE` 仍然可用（代码按 `MAIL_USER → QQ_EMAIL` 双读），已经配好的不用改。
5. **用 163 / 126 邮箱**再配 Variables（同一个页面的 *Variables* 标签页，不是 Secrets）：`IMAP_HOST=imap.163.com`（126 则是 `imap.126.com`），`IMAP_PORT` 留空即 993。QQ / foxmail 不用设，默认值就是它。163 的授权密码在邮箱设置里开启 IMAP/SMTP 服务后生成（会要求先绑手机）。**不需要为 163 改任何代码**——Action 本来就会发送 IMAP `ID` 命令，而网易与 QQ 一样要求它。不支持 Outlook / Office365（微软已关闭 IMAP 的密码登录，必须走 OAuth2）；Gmail 可用但需要 App Password。同一个 Variables 页面还有可选的 `MAIL_TZ_OFFSET`（v4.24.0，默认 `+08:00`）：把邮件里「3 日内 / 48 小时内」这类**相对期限**换算成绝对时间时用的时区，不在中国时区、或邮箱收信时区不同才需要改。
6. 先手动跑 `connectivity-test` 验证能登录（只登录不拉邮件，30 秒内就能区分“凭据 / 主机配错了”与“被服务商风控”），再启用定时任务 `mail-sync`。定时是**每 3 小时触发一次**，但真正的拉取频率由「最小间隔」决定，默认 12 小时——所以不设任何东西时行为与旧版一致；想改成 3 / 6 小时就在网页端「邮件提醒 → 设置 → 拉取间隔」里填，被跳过的那些运行不连邮箱、不调 AI（0 token）。
7. 回到网页「邮件提醒」点「重新读取」，即可看到建议（导航角标显示待复核数量）。

复核与应用：

- 每张建议卡按公司名模糊匹配你的台账：命中 1 条直接显示；**命中多条时可勾选多条一起应用**（v4.15.0 起——一封测评 / AI 面通知常常覆盖同一家公司的多个岗位，旧版单选下拉要点 N 次，而第一次应用后邮件就被标记成已处理、剩下的再也关联不上）。同一家公司的候选默认全勾，**跨公司的候选默认全不勾并给出警告**，强制你逐条确认。没命中可「新建记录」预填邮件信息。
- 每个字段都能**就地改了再应用**（v4.16.0 起）：推进里程碑（阶段下拉 + 日期 + 备注）、**截止时间**（笔试 / 测评邮件里最有用的「链接 X 日失效 / 请在 X 日前完成」，会写进台账的「关键时间 · 截止」并参与倒计时）、安排时间、最近安排、下一步行动，全部是内联输入框，不必先应用再回台账改一遍。勾选要采纳的字段后点「应用所选」写入；点「忽略」则本机不再显示。时间类字段是**日期 + 时刻两个框**（v4.24.0）：时刻留空即"只有日期"，填了就是精确到分的定时时刻——邮件里写清的「9 月 17 日 18:00 前」现在能完整落进台账，不再只剩一个 `9/17`。
- **截止时间写成「3 日内」「48 小时内」时**（v4.24.0）：AI 会以**收信时刻**为基准换算成绝对时间写入，并在截止时间旁标一枚蓝色**「按邮件推算」**，鼠标悬停能看到邮件里的原文表达（在手机上点一下也能看到）。这枚标记是刻意加上的：算出来的日期看起来和邮件里写死的毫无区别，不标出来你不会想到要去核对一次换算。基准时刻的时区由 Action 仓库的一个变量 `MAIL_TZ_OFFSET` 决定（同一个 Variables 页面，默认 `+08:00`，可用 `+09:00` / `+00:00` 等；认不出的写法会回落到 `+08:00`，不会当成 0 时区）。换算只由 AI 做一次，网页端原样展示、不重算，所以你在卡片上改了日期就会以你改的为准。
- **所有更新都要你手动确认，绝不自动写入**；置信度低（<0.6）的建议会标黄，请仔细核对后再应用。
- “相关邮件（v4.20.0 / v4.22.0 / v4.26.0）”：应用一封建议后，**这封邮件会挂到目标记录上**（新建记录那条路径同样会挂）。之后打开该记录的详情抽屉，就能看到「相关邮件」——类型 / 主题 / 发件人 / 收信时间 / AI 摘要，倒序排列；点「查看邮件原文」**就地展开正文**（v4.22.0，正文超过 2000 字会截断）。此前的「在邮件提醒中查看」已移除——已应用 / 已忽略的邮件本来就不在待复核列表里，点过去只会扑空。
  **邮件里的链接可以直接点（v4.26.0）**：测评 / 笔试邮件最有用的往往是那条「点击开始测评」的地址，而它此前根本到不了你手上——Action 把 HTML 转成纯文本时会把链接的 `href` 整段剥掉（HTML-only 的邮件到这一步只剩「点击这里开始测评」几个字），而归档正文又只留 2000 字（地址常写在邮件末尾）。现在 Action 会**单独把链接抽出来**存成一条字段：只认 `http`/`https` 绝对地址，退订 / 隐私政策这类每封都有的模板链接会被丢掉，一封最多 8 条；打开记录详情就能看到一排**可点的地址胶囊**，点一下直接跳去测评页，不必回邮箱翻。邮件原文里的地址也会自动变成可点链接（前提是它本来就写在纯文本里）。**两点要留意**：① 测评链接常带一次性 token，它和正文一样随归档进 Gist——没设同步口令时是明文，在意的话请设口令或配 `MAIL_ENC_KEY`；② 地址是**代码抽取**的（不是 AI 猜的），但**已经归档过的旧邮件不会自动长出链接**：那封邮件早已越过水位线，Action 不会再解析它。想补，按下面「怀疑漏了邮件」那节的做法手动回溯重扫一次，再回网页「邮件提醒」点一次「重新读取」，同步时会把链接回填进已有归档（与正文回填同一条路，只补空的、不覆盖已有）。
  正文归档**不需要任何密钥**（v4.23.0 起）：应用邮件时正文会一并存下来，「查看邮件原文」点开就能看。代价是——**没设同步口令时，正文会以明文写进 Gist**，而 secret gist 凭链接就能被读取。在意的话请设「同步口令」：设了之后记录与正文一起变成密文，GitHub 只保存密文。云同步弹窗里的「云端存储」一行会实时标注当前是**密文还是明文**，不必自己推断。旧建议（v4.23.0 之前生成的）没带回正文，详情里会写明「还没有正文快照」；只要那封邮件还在云端候选里，重跑一次 Action 的 mail-sync 后，本机同步时会**自动用建议里的正文回填空归档**（v4.23.1，只补空的、不覆盖已有正文），不必重新应用；已被清理（30 天 / 100 条）或应用得太早（v4.20.0 之前，记录上根本没有邮件引用）的补不回来。
  邮件的关联用**稳定标识**：Message-ID 优先，没有它时用「邮箱 + UIDVALIDITY + UID」组合，所以换邮箱、服务器重开、建议过期被清理（30 天 / 100 条）之后关联都还在；跨设备同步时对关联与归档取**并集**，一端新增的不会被另一端的旧版本盖掉。同一封邮件**改期重投会替换旧时间**（v4.22.0），不会同时挂着两个面试时间。
- 里程碑日期旁边有一枚**来源标注**：绿色「来自邮件」= AI 从正文里读到的；橙色「收信日兜底」= 邮件没给时间、代码用收信日顶上（**这是编造值，请改掉或不勾这个字段**）；灰色「疑似收信日」= 这条建议产生于 v4.16.0 之前、没有记录来源，但日期正好等于收信日，所以倾向警示。缺日期时点「应用所选」会被直接拦下来让你填，不会静默写进时间线。

怀疑漏了邮件（v4.6.1）：

- 状态栏会显示本次**丢弃了多少封**，展开可看每封被丢邮件的**发件人、主题、邮件编号与丢弃原因**（发件人是邮件系统 / 主题像营销 / 无关键词 / AI 判非招聘 / 低置信 / AI 失败）。自动预筛必然要丢东西，关键是丢得可查。
- 若发现某封招聘邮件被误丢：在 `autumn-mail-sync` 仓库手动运行 `mail-sync`，填 `UID_FROM=<那封邮件的编号>` 并把 `MAX_PER_RUN` 调大，即可回溯重扫。**常规增量运行不会回头看已被水位越过的邮件**，所以必须手动回溯。
- 若丢弃原因反复是「主题与正文都没命中预筛关键词」，在「邮件提醒 → 设置」里给关键词补词即可（如补上你目标行业的专有词），无需改代码。
- 招聘系统常用的 `noreply` 类发件人（Moka / 北森 / 牛客 / 各大厂校招门户）**不会**被当成营销噪声丢弃；主题写着「面试邀请 / 笔试通知 / 录用通知」的邮件会无条件放行进 AI 判定。

设置、加密与跨设备（v4.3.0）：

- **跨设备同步**：在某台设备「忽略 / 应用」过的邮件建议，会随云同步到其它设备，不再重复出现，无需逐台点击。
- **网页端设置**：视图右上「设置」可调预筛关键词、置信度阈值、回看天数、单次上限、**启用开关**、**最小运行间隔**、**AI 附加指令**（如"只关注互联网/国企"）与**整体替换解析提示词**（v4.7.0，见下）。保存后写入你自己 Gist 的 `mail-config.json`（明文、不含密钥），Action 下次运行读取生效；关闭开关或间隔未到时 Action 直接跳过、**0 token**。
- **AI 提示词可见可改（v4.7.0）**：设置面板里点「查看当前实际生效的完整提示词」，能看到 Action 上次运行时**真正发给 AI 的全文**——它由 Action 自己写进云端，所以展示的永远等于生效的，不是一份可能过期的副本。想改变 AI 的理解方式（例如"只看国企与事业单位""summary 必须写明截止时间"），可以填「整体替换解析提示词」；**清空即恢复内置**。注意末尾的「输出契约 · 不可覆盖」段落（只返回 JSON、字段清单、阶段仅限 14 个预设、不得编造）**无法被删掉**，它会强制附加在你的提示词之后——这是故意的：契约一旦被改，Action 会解析不到任何字段，建议队列将永远为空却仍显示运行成功。改完要等 Action 下次运行才生效，届时快照也会更新。
- **里程碑备注（v4.7.0）**：建议卡上「推进里程碑：已投递（2026-09-06） · …」后面那段备注，勾选应用后会**永久写进台账时间线**。邮件类型明确时显示类型（如「邮件·测评」），类型是「其它」（投递确认、宣讲预告、系统认证这类）时改用 AI 写的内容摘要，例如「邮件·简历成功投递滴滴校招，等待后续流程推进」——三个月后回看台账才知道这条是什么。此前一律显示「邮件·其它」，等于什么都没说。已入库的旧建议也会自动用摘要展示，不需要重新扫描。你自己手写的备注不会被改写。
- **邮件加密（可选，推荐）**：Action 侧配置 `MAIL_ENC_KEY` Secret 后，`mail-suggestions.json` 会加密存储（正文也在其中），**这一项配不配都不影响「看邮件原文」**——正文照样归档。在「工具 → 云同步」弹窗的「邮件解密密钥」里填**完全相同**的密钥（可点「生成」再复制到 Secret）即可解密查看；**留空则回落到用同步口令解密**，所以更省事的做法是把 `MAIL_ENC_KEY` 设成与同步口令**同一串**，网页端留空即可——换设备只需要填一次口令，不必每台设备再手输一次密钥（v4.23.0）。密钥只存本机，不上传 Gist。这样即便有人拿到你的 Gist 链接，也读不到建议文件的明文（GitHub 的 secret gist 凭链接本可被访问）。
- 密钥类（QQ 授权码 / AI Key / GIST_PAT / MAIL_ENC_KEY）永远只在你的私有仓库 Secrets 与本机，不会进网页、不会进台账数据。

隐私与注意：

- QQ 授权码、AI Key、Gist 令牌只存在你的私有仓库 Secrets，永不进浏览器、不进网页本地存储。
- 邮件正文只发往你自己配置的 AI 端点；建议结果明文存在你自己的私有 Gist。
- 改过 QQ 密码后授权码会失效，视图顶部会红条提示并附「怎么修复」；重新生成授权码并更新 Secret 即可。
- 「已应用 / 已忽略」只记在本机，不跨设备同步。

## 七、重要说明

- 网页功能更新后，设备会逐步获取新版本。
- 投递记录不会在电脑和手机之间自动同步。
- 同一网址在不同设备、不同浏览器中也是独立数据。
- 需要换设备时，请将旧设备导出的 JSON 文件传到新设备，再在新设备中导入。
